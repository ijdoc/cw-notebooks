# Session snapshots are committed so molab serves a pre-rendered notebook

molab renders a notebook far better when the repository carries a session snapshot alongside it, produced by `uvx marimo export session <notebook>` (with `--sandbox` to use the notebook's own inline dependencies). Without one, a customer opening a molab link sees an empty notebook and has to execute it before anything appears — against an endpoint they may not yet have a key for. So snapshots are generated and **committed**.

## Consequences

- **A snapshot captures rendered output, and rendered output is published.** This is the sharpest edge of [ADR-0001](0001-no-customer-or-private-information-ever.md): a notebook that displays a truncated API key, an entity name, or a response containing real data will preserve it in the snapshot, in git, forever. Review the snapshot's content, not just the notebook's source, before committing.
- Snapshots go stale when a notebook changes and must be regenerated in the same commit, or the preview shows output that no longer matches the code.
- A snapshot is generated by actually running the notebook, so it costs real tokens against the live endpoint and requires a working key at authoring time.
